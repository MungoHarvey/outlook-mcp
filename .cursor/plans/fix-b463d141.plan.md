# Outlook MCP: Schema Fix and Hardening Plan

## Scope

- Fix invalid JSON Schema for the "create-event" tool (`attendees` array missing `items`).
- Add robust runtime validation and error handling.
- Add tests (unit + integration) and verify LangChain/OpenAI compatibility.
- Align with MCP best practices for observability, health, and deployment readiness.

## Key Changes

1) Map and validate the current architecture

- Inspect tool registration in `index.js` and calendar tool definitions in `calendar/` (likely `calendar/event-utils.js`, `calendar/index.js`).
- Confirm the single source of truth for the "create-event" tool schema.

2) Repair tool JSON Schema (array of email strings)

- In the tool schema for `create-event`, change `attendees` to include `items`:
```json
{
  "type": "array",
  "description": "List of attendee email addresses",
  "items": { "type": "string", "format": "email" }
}
```

- Ensure all other fields use draft-07 compatible JSON Schema (e.g., `start`/`end` as `string` + `format: date-time`).

3) Add runtime input validation

- Introduce AJV (JSON Schema validator) or zod→json schema at tool boundary.
- Validate incoming tool parameters before execution; return structured MCP errors on validation failures.

4) Strengthen error handling and logging

- Standardize error responses with codes and user-safe messages.
- Add structured logs around tool invocation, validation errors, and upstream API failures.

5) Tests

- Unit tests: schema validity (compile with AJV), positive/negative cases for `attendees` and datetime fields.
- Integration: simulate MCP tool discovery and invocation; ensure OpenAI/LangChain clients accept the tool.
- Smoke run: create a test event against a mock or Microsoft Graph sandbox.

6) Client compatibility checks

- Verify with OpenAI function calling and LangChain tool wrappers that discovery/register succeeds and invocation works end-to-end with valid parameters.

7) Operational hardening (best practices)

- Health endpoints or lightweight health checks around Outlook auth and Graph API reachability.
- Add rate limiting and basic retries with backoff for Graph requests.
- Add metrics counters for tool success/error and latency.

8) Optional temporary workaround

- Add a feature flag to skip/disable the invalid tool at boot (for immediate unblock) until fixed.

9) Documentation

- Update `README.md` and `USER-CONFIG-README.md` with parameter examples for `create-event`, validation rules, and client usage notes for OpenAI/LangChain.

## Files likely to be edited

- `calendar/event-utils.js` (schema/data shaping)
- `calendar/index.js` (tool registration/handlers)
- `index.js` (global tool registry and server wiring)
- `config.js` (feature flags; health/metrics toggles)
- `README.md`, `USER-CONFIG-README.md` (docs)
- `test/` (new tests)

## Acceptance criteria

- Tool discovery succeeds in OpenAI and LangChain without schema errors.
- Unit tests pass: schema compiles; invalid `attendees` rejected; valid payload accepted.
- Integration test can create an event (mock/sandbox) with attendees as strings.
- Logs show structured validation and error messages.
